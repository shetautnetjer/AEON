# Offline lifecycle repair and proposed full diagnostic

The [first diagnostic](tempo-shutdown-diagnostic-result-2026-09-30.md) stopped at its required first-shutdown gate. Its 15 minutes were a maximum deadline including cleanup, not a minimum soak. It verified initial synthetic traces and metrics but did not complete restart, durability readback or the second shutdown. Both failed runs and their state remain unchanged; this repair cannot qualify them retrospectively.

## Observed defects and bounded repair

The removed Tempo cgroup could raise `FileNotFoundError` before cleanup requested normal shutdown of its still-active peers. Missing evidence must remain unverified while each independently owned peer receives bounded normal shutdown. Verification failure must not widen forced targets, and failure receipts must survive. Tests reproduce directory removal through real temporary filesystem operations and replay the observed terminal property values rather than keeping an idealized zero counter alive.

Successful inactive systemd units can be garbage-collected, clearing their exit/accounting metadata. A persistent local D-Bus connection holds `RefUnit()` references for the run's exact units. Retained exit data must match Tempo's observed invocation, process and monotonic start/exit times; connection or manager-owner loss, reset properties, a new invocation or unknown status cannot qualify as exit zero. `Result=success` or a lifecycle message alone is insufficient. The initial bus handshake and every method call have separate checks against the existing phase deadline; reconnecting cannot restore an earlier reference.

The pilot gets one dedicated **no-process accounting slice**, `app-aeonTempoCheck<run-id>.slice`, under the existing `app.slice`. Its only permitted descendants are the four pilot services and the synthetic emitter. Its aggregate maximum is 2,176 MiB / 225% CPU, zero swap and 576 tasks, encompassing the unchanged per-component ceilings. `StopWhenUnneeded=no` keeps it active through child removal. Capture hierarchical `memory.events` at a fresh zero baseline and after workload termination, while this same slice remains active, before explicitly stopping it. Both allocation-related `oom` and `oom_kill` are required. A positive aggregate fails without claiming which child caused it.

The accounting proof requires the same owned directory identity, applicable cgroup2 mount without `memory_localevents`, complete descendant coverage and no counter decrease. Missing files, `ENODEV`, lost identity, escaped or foreign children, changed mount behavior or positive counters remain failed/unverified. An open file descriptor does not make deleted kernfs counters readable. A shared ancestor's unrelated events are not substituted for this isolated scope. Slice stop is allowed only after verified children are gone; stopping a slice with foreign children could stop those children and is refused.

## Versioned documentation and verification boundary

Local versions: systemd/libsystemd **259.5-0ubuntu3.4**, kernel **7.0.0-31-generic**. The already installed `/usr/lib/x86_64-linux-gnu/libsystemd.so.0.42.0` is pinned at SHA-256 `9405c27411b652140806ab7576f7d76610f67bde662ba730efc7aa7171785011`. No library or package acquisition is proposed.

The implementation references upstream [systemd v259.5 unit collection/reference handling](https://github.com/systemd/systemd/blob/v259.5/src/core/dbus-unit.c#L642), [active slice lifecycle](https://github.com/systemd/systemd/blob/v259.5/src/core/slice.c#L207), [cgroup pruning](https://github.com/systemd/systemd/blob/v259.5/src/core/cgroup.c#L2649), and [sd-bus handshake/call behavior](https://github.com/systemd/systemd/blob/v259.5/src/libsystemd/sd-bus/sd-bus.c). Linux [v7.0 hierarchical memory events](https://github.com/torvalds/linux/blob/v7.0/mm/memcontrol.c), [v7.0 cgroup v2 documentation](https://github.com/torvalds/linux/blob/v7.0/Documentation/admin-guide/cgroup-v2.rst), and [kernfs deactivation](https://github.com/torvalds/linux/blob/v7.0/fs/kernfs/file.c) establish the counter conditions and removal failure. Installed binaries and the actual runtime remain authoritative over upstream assumptions.

Context7 was consulted. It found systemd coverage but advertised v261.3 rather than the installed v259.5; its discovery results were not treated as version-matched proof. `RemainAfterExit` and `ExecStopPost` were considered but cannot alone guarantee final cgroup counters. systemd 259's `OOMKills` excludes allocation-only `oom`, so it does not replace the strict counter requirement. Tempo 3.1.0's [SIGTERM shutdown-delay default](https://github.com/grafana/tempo/blob/v3.1.0/cmd/tempo/app/config.go#L86) is distinct from its observed 30-second backend-worker allowance.

The installed v259.5 validator also identified `CPUAccounting=` as removed/ignored; the host omits that readback property. The new slice therefore uses supported `MemoryAccounting=true`, `CPUQuota=225%` and a checked kernel `cpu.max`, with no obsolete CPU-accounting boolean. This matches [v259.5 configuration parsing](https://github.com/systemd/systemd/blob/v259.5/src/core/load-fragment-gperf.gperf.in#L212) and [CPUQuota semantics](https://github.com/systemd/systemd/blob/v259.5/man/systemd.resource-control.xml#L208). The host-level inert check exposed this mismatch; new tests replay the omitted property while still rejecting an incorrect kernel quota.

The earlier passing tests missed the joint lifecycle transition: removed Tempo counters before peer cleanup, plus successful unit metadata reset. Their normal-stop fixture kept counter files and supplied `ExecMainCode=1`; deletion tests checked unknown qualification after stopping, without asserting that still-active peers received normal shutdown. New filesystem/lifecycle tests exercise deletion before cleanup and reset properties. The newly introduced keeper also has native-ABI-seam tests for stalled handshake and connection loss. Passing these tests establishes offline behavior for the covered cases; it does not establish live kernel propagation or systemd retention across an actual stop. Those remain the purpose of the next finite diagnostic.
